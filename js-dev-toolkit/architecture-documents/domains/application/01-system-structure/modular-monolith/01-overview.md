# 모듈러 모놀리스 개요

## 비유: 아파트 건물

```
일반 모놀리스 (오픈 플로어)        모듈러 모놀리스 (방이 구분된 아파트)
┌────────────────────┐           ┌──────────┬──────────┬──────────┐
│                    │           │  주문 방  │  결제 방  │  회원 방  │
│  코드가 뒤섞여 있음  │    →      │  (잠김)   │  (잠김)   │  (잠김)   │
│  어디서든 어디든 접근 │           ├──────────┴──────────┴──────────┤
│                    │           │         공용 복도 (인터페이스)        │
└────────────────────┘           └─────────────────────────────────┘
```

방들은 잠겨 있다. 다른 방에 들어가려면 **문(인터페이스)을 통해서만** 가능하다.  
하지만 모두 같은 건물 안에 있어 **배포는 하나**다.

---

## 3가지 아키텍처 비교

```
일반 모놀리스          모듈러 모놀리스           MSA
┌──────────────┐     ┌──────────────┐     ┌──────┐ ┌──────┐ ┌──────┐
│ 주문          │     │ [주문 모듈]   │     │ 주문  │ │ 결제  │ │ 회원  │
│ 결제          │     │ [결제 모듈]   │     │ 서비스│ │ 서비스│ │ 서비스│
│ 회원  (뒤섞임)│     │ [회원 모듈]   │     └──┬───┘ └──┬───┘ └──┬───┘
│ 상품          │     │              │        │        │        │
└──────────────┘     │ ─── 경계 ─── │     네트워크 통신 (HTTP/이벤트)
    단일 배포          └──────────────┘
                          단일 배포
```

| 기준 | 일반 모놀리스 | 모듈러 모놀리스 | MSA |
|---|---|---|---|
| 배포 단위 | 1개 | 1개 | N개 |
| 코드 경계 | 없음 | 명확 | 명확 |
| 팀 독립성 | 낮음 | 중간 | 높음 |
| 운영 복잡도 | 낮음 | 낮음 | 높음 |
| DB | 공유 | 공유 (소유권 분리) | 서비스별 분리 |
| 분산 트랜잭션 | 불필요 | 불필요 | 복잡함 |
| 적합 규모 | 소규모 | 중규모 | 대규모 |

---

## 언제 선택하는가?

```
팀이 작고 서비스가 성장 초기인가?
  Yes → 일반 모놀리스 (단순함 우선)
  
성장했지만 MSA 운영 인프라가 부담스러운가?
  Yes → 모듈러 모놀리스 ✅
  
팀이 크고 서비스별 독립 배포가 필수인가?
  Yes → MSA
```

> **모듈러 모놀리스의 핵심 가치**: MSA의 코드 구조적 이점을 취하면서,  
> 분산 시스템 복잡성(네트워크 장애, 분산 트랜잭션, 서비스 디스커버리)은 피한다.

## 실무 채택 사례

- **Shopify**: 거대한 Rails 앱을 모듈러 모놀리스로 정리, MSA 전환 중간 단계로 활용
- **Stack Overflow**: MSA 대신 모듈러 모놀리스 유지 (소규모 팀에 MSA는 과도함)
