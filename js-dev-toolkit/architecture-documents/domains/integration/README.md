## 이 영역에서 다루는 것

시스템 사이의 API, 메시지, 이벤트와 업무 흐름을 다룹니다. 호출 계약과 데이터 전달 방식뿐 아니라 실패·중복·재시도가 발생했을 때 업무 결과를 어떻게 유지할지도 함께 정리합니다.

- **핵심 질문:** 한 시스템의 요청이나 변경 사항을 다른 시스템에 어떤 계약과 전달 방식으로 연결할 것인가?
- **정리할 산출물:** API·이벤트 계약, 연계 흐름도, 실패 처리 규칙, 업무 보상 절차입니다.

## 읽는 순서와 활용 방법

1. 기존 Event-Driven 본문의 개요와 패턴을 읽고 발행자·소비자·브로커의 관계를 파악합니다.
2. 요청·응답이 필요한 부분과 비동기 전달이 가능한 부분을 나누고 계약을 정의합니다.
3. 중복, 순서 변경, 지연, 부분 실패를 가정하여 재시도와 보상 규칙을 정리합니다.

## 다른 영역과의 경계

이벤트를 전달하고 소비하는 흐름은 이 폴더에 둡니다. 이벤트를 상태의 원본으로 저장하고 재구성하는 Event Sourcing은 data에서 다룹니다. 서비스 자체를 나누는 기준은 application 문서와 연결합니다.
