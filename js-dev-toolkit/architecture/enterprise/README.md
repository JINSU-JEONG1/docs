## 이 영역에서 다루는 것

조직 전체의 업무, 정보, 애플리케이션, 기술을 어떤 방향으로 정리할지 다룹니다. 개별 시스템을 설계하기 전에 공통 기준과 투자·전환의 우선순위를 정할 때 사용합니다.

- **핵심 질문:** 여러 시스템의 중복 기능을 줄이고 공통 기술 기준을 세우려면 어디부터 정리해야 하는가?
- **정리할 산출물:** 업무 역량 맵, 시스템 목록, 기술 표준 목록, 단계별 전환 로드맵입니다.

## 읽는 순서와 활용 방법

1. 업무 역량과 가치 흐름을 정리해 조직이 수행하는 일을 파악합니다.
2. 정보 구조와 애플리케이션 목록을 함께 보고 중복·누락·책임 경계를 찾습니다.
3. 기술 표준과 예외 기준을 정한 뒤, 의존성과 우선순위에 따라 전환 로드맵을 작성합니다.

위 순서는 본문을 작성하거나 설계를 진행할 때의 순서입니다. 현재 학습 가능한 상세 문서는 [전체 안내의 바로 읽을 수 있는 문서](../README.md#바로-읽을-수-있는-문서)에서 확인할 수 있습니다.

## 다른 영역과의 경계

특정 서비스의 요청 처리 흐름과 배포 구조는 솔루션 아키텍처에서 구체화합니다. 이 폴더에는 여러 시스템에 공통으로 적용할 방향과 기준을 둡니다.

## 문서 작성 기준

각 본문에는 문제와 적용 조건, 핵심 구조, 예시, 장단점, 운영 시 확인할 사항, 근거 자료를 순서대로 정리합니다. 특정 선택을 권장할 때에는 전제와 제약을 함께 적습니다.

작성 예정 파일에 본문을 채우면 이 표의 상태를 갱신합니다. 파일의 단계 접두사를 변경하면 [전체 안내](../README.md)와 이 문서에서 해당 파일을 가리키는 링크도 함께 수정합니다.
