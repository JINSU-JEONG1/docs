## 이 영역에서 다루는 것

하나의 업무 문제를 해결하는 시스템 전체의 설계를 다룹니다. 사용자 요구부터 애플리케이션·데이터·연계·인프라·보안까지 연결하여, 실제로 구현하고 운영할 수 있는 구조를 정리하는 곳입니다.

- **핵심 질문:** 이 업무 요구를 충족하려면 어떤 구성요소가 필요하고, 서로 어떻게 연결되어야 하는가?
- **정리할 산출물:** 시스템 경계도, 품질 요구사항, 전체 구성도, 대안 비교표, 전환 계획입니다.

## 읽는 순서와 활용 방법

1. 사용자, 외부 시스템, 업무 범위와 제약을 확인합니다.
2. 성능·가용성 등 품질 요구를 측정 가능한 시나리오로 정리합니다.
3. 주요 요청과 데이터의 전체 흐름을 그리고, 대안을 비교해 선택 근거를 남깁니다.
4. 데이터 이전, 서비스 전환, 검증과 롤백까지 포함해 실행 순서를 정합니다.

현재는 [03 전체 흐름 설계](<[draft]03-end-to-end-design.md>)를 먼저 읽을 수 있습니다. 위 번호는 요구사항부터 전환까지 설계를 진행하는 순서이며, 다른 상세 문서는 [전체 안내의 바로 읽을 수 있는 문서](../README.md#바로-읽을-수-있는-문서)에서 확인할 수 있습니다.

## 문서 작성 기준

각 본문에는 문제와 적용 조건, 핵심 구조, 예시, 장단점, 운영 시 확인할 사항, 근거 자료를 순서대로 정리합니다. 특정 선택을 권장할 때에는 전제와 제약을 함께 적습니다.

작성 예정 파일에 본문을 채우면 이 표의 상태를 갱신합니다. 파일의 단계 접두사를 변경하면 [전체 안내](../README.md)와 이 문서에서 해당 파일을 가리키는 링크도 함께 수정합니다.
