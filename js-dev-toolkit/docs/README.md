# 📂 소프트웨어 개발 산출물 목록 (Software Artifacts List)

본 문서는 프로젝트 수행 단계별로 생성되는 공식 산출물의 목록과 목적을 정의합니다. 프로젝트의 투명한 관리, 팀원 간의 원활한 소통, 그리고 향후 유지보수의 효율성을 높이기 위해 활용됩니다.

---

## 📌 단계별 산출물 상세 가이드

### 1. 계획 단계 (Planning Phase)
프로젝트의 목표와 범위를 명확히 하고, 성공적인 리스크 관리를 위한 기준을 세웁니다.

* **프로젝트 계획서 (Project Management Plan / PMP)**
  * **목적:** 프로젝트의 개요, 마일스톤, 투입 인력, 예산 및 일정 관리의 기준을 수립하여 프로젝트가 기한 내에 완료되도록 리드합니다.
* **위험 관리 계획서 (Risk Management Plan / RMP)**
  * **목적:** 프로젝트 진행 중 발생할 수 있는 기술적·일정적·인적 리스크를 사전에 식별하고, 이에 대한 예방 및 비상 대응 방안(Mitigation Plan)을 마련합니다.
* **품질 보증 계획서 (Quality Assurance Plan / QAP)**
  * **목적:** 산출물과 최종 소프트웨어가 설정된 품질 표준을 준수하는지 검증하기 위한 프로세스, 감사(Audit) 일정, 품질 기준을 정의합니다.

---

### 2. 요구사항 분석 단계 (Requirements Analysis Phase)
발주처와 사용자의 요구사항을 명확하게 파악하여 개발 범위를 확정합니다.

* **요구사항 정의서 (Software Requirements Specification / SRS)**
  * **목적:** 시스템이 반드시 갖추어야 할 기능적 요구사항과 성능·보안 등의 비기능적 요구사항을 상세히 기록하여 개발 팀과 고객 간의 최종 합의점을 도출합니다.
* **요구사항 추적표 (Requirements Traceability Matrix / RTM)**
  * **목적:** 정의된 요구사항이 설계, 구현, 테스트 단계에서 누락되지 않고 모두 반영되었는지 추적하여 프로젝트 범위의 왜곡을 방지합니다.
* **인터페이스 정의서 (Interface Control Document / ICD)**
  * **목적:** 연계 대상 내부 모듈 또는 외부 시스템 간의 데이터 통신 방식, 프로토콜, 데이터 규격을 명시하여 이기종 시스템 간의 안정적인 연동을 보장합니다.

---

### 3. 설계 단계 (Design Phase)
분석된 요구사항을 바탕으로 구체적인 시스템 구조, 화면 구조, 데이터베이스 모델을 시각화하고 사양화합니다.

* **기본 설계서 (System Architecture Design / SAD)**
  * **목적:** 시스템의 전체 구조(HW/SW 아키텍처), 네트워크 구성, 서버 레이아웃을 정의하여 개발 시스템의 뼈대를 구축합니다.
* **소프트웨어 구성도 (Software Component Diagram / SCD)**
  * **목적:** 소프트웨어를 구성하는 컴포넌트 간의 의존성과 관계를 구조적으로 표현하여 개발 모듈화의 지침을 제공합니다.
* **UI/UX 화면 설계서 (User Interface Design / Storyboard / UID)**
  * **목적:** 와이어프레임과 스토리보드를 통해 화면의 흐름, 인터랙션, 사용자 경험을 미리 시각화하여 프론트엔드 개발자와 UI 디자이너의 작업 가이드를 제공합니다.
* **데이터베이스 설계서 (Database Design Document / DBDD)**
  * **목적:** ERD(논리/물리), 테이블 정의서, 코드 정의서를 통해 데이터의 구조와 무결성을 정의하고 효율적인 데이터 저장을 도출합니다.
* **프로그램 목록 및 사양서 (Program List & Detail Specification / PLDS)**
  * **목적:** 개발해야 할 프로그램 단위를 목록화하고 개별 모듈의 로직, 입출력 값, 처리 절차를 명세하여 백엔드 개발자의 구현 속도와 정확도를 높입니다.

---

### 4. 구현 및 구축 단계 (Implementation Phase)
설계서를 바탕으로 소스코드를 작성하고, 실제 구동 가능한 개발 및 운영 환경을 세팅합니다.

* **소스 코드 (Source Code / SC)**
  * **목적:** 설계 사양을 바탕으로 실제 동작하는 소프트웨어를 프로그래밍 언어로 구현한 프로젝트의 핵심 최종 결과물입니다.
* **개발 환경 구축 가이드 (Development Environment Setup Guide / DESG)**
  * **목적:** 신규 팀원이나 운영자가 개발 서버, 데이터베이스, 형상 관리를 동일하게 세팅할 수 있도록 빌드 및 배포(CI/CD) 절차를 문서화합니다.
* **버전 관리 내역 (Version Control History / VCH)**
  * **목적:** 형상 관리 시스템을 통해 소스코드의 수정 이력을 추적하고, 충돌 방지 및 특정 시점으로의 코드 롤백(Rollback)을 가능하게 합니다.

---

### 5. 테스트 단계 (Testing Phase)
개발된 소프트웨어가 요구사항 정의서와 일치하며 오류 없이 동작하는지 철저히 검증합니다.

* **테스트 계획서 (Test Plan / TP)**
  * **목적:** 테스트의 전체 범위, 일정, 환경, 투입 인력, 합격 기준을 정의하여 단위·통합·E2E·인수 테스트에 걸친 체계적인 검증 활동이 이루어지도록 일정을 수립합니다.

#### 5-1. 단위 테스트 (Unit Test / UT)
* **단위 테스트 케이스 (Unit Test Case / UTC)**
  * **목적:** 개별 함수·모듈 단위의 입력/출력 조건과 예상 결과를 정의하여 코드 단위의 정확성을 검증합니다.
* **단위 테스트 결과서 (Unit Test Report / UTR)**
  * **목적:** 단위 테스트 수행 결과와 코드 커버리지를 기록하여 개별 모듈의 품질을 확인합니다.

#### 5-2. 통합 테스트 (Integration Test / IT)
* **통합 테스트 케이스 (Integration Test Case / ITC)**
  * **목적:** 모듈 간의 인터페이스 및 데이터 흐름을 검증하기 위한 테스트 조건과 절차를 정의합니다.
* **통합 테스트 결과서 (Integration Test Report / ITR)**
  * **목적:** 모듈 간 연동 테스트 수행 결과를 기록하여 인터페이스 오류 및 데이터 흐름 이상을 확인합니다.

#### 5-3. E2E 테스트 (End-to-End Test / E2E)
* **E2E 테스트 시나리오 (End-to-End Test Scenario / E2E-TS)**
  * **목적:** 실제 사용자 관점에서 전체 비즈니스 흐름을 처음부터 끝까지 시뮬레이션하여 시스템 전반의 동작을 검증합니다.
* **E2E 테스트 결과서 (End-to-End Test Report / E2E-TR)**
  * **목적:** E2E 테스트 수행 결과와 발견된 결함을 기록하여 실제 운영 환경 배포 전 최종 품질을 확인합니다.

#### 5-4. 인수 테스트 (User Acceptance Test / UAT)
* **인수 테스트 시나리오 (User Acceptance Test Scenario / UAT-TS)**
  * **목적:** 발주처 또는 최종 사용자가 실제 업무 흐름 기준으로 직접 검증할 수 있도록 비즈니스 시나리오를 정의합니다.
* **인수 테스트 결과서 (User Acceptance Test Report / UATR)**
  * **목적:** 발주처 또는 최종 사용자가 시스템을 검증한 결과를 기록하고, 요구사항 충족 여부를 최종 승인합니다.

#### 5-5. 결함 관리
* **결함 관리 대장 (Defect Management Log / DML)**
  * **목적:** 테스트 전 단계에서 발견된 결함의 발생, 처리, 종결 이력을 추적 관리하여 배포 전 모든 결함이 해소되었음을 보증합니다.

---

### 6. 이행 및 유지보수 단계 (Transition & Maintenance Phase)
시스템을 상용 환경으로 안전하게 전환하고, 사용자가 시스템을 원활히 사용할 수 있도록 지원합니다.

* **사용자 지침서 (User Manual / UM)**
  * **목적:** 일반 사용자가 시스템의 기능과 화면을 올바르게 사용할 수 있도록 기능별 활용 가이드와 FAQ를 제공합니다.
* **운영자 지침서 (Operation Manual / OM)**
  * **목적:** 시스템 관리자가 서버 관리, 모니터링, 데이터 백업 및 장애 발생 시 긴급 복구를 수행할 수 있도록 절차를 안내합니다.
* **설치/이행 계획서 (Deployment & Transition Plan / DTP)**
  * **목적:** 기존 구버전 데이터의 이관(Migration), 상용 서버 설치 절차, 오픈 당일 모니터링 계획을 수립하여 시스템 다운타임을 최소화하며 안정적으로 오픈합니다.
