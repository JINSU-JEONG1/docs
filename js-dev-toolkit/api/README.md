# API

시스템끼리 기능과 데이터를 주고받기 위한 인터페이스입니다. 통신 방식, 계약, 설계와 검증으로 나누어 다룹니다.

## 통신 방식

| 폴더 | 설명 |
|---|---|
| [rest](rest/) | 리소스를 중심으로 HTTP 메서드와 상태 코드를 사용하는 API 설계 방식입니다. |
| [grpc](grpc/) | 서비스와 메시지를 정의하고 클라이언트가 원격 서버의 기능을 호출하는 RPC 프레임워크입니다. |
| [graphql](graphql/) | 스키마를 바탕으로 클라이언트가 필요한 데이터의 형태를 지정하는 API 쿼리 언어와 실행 방식입니다. |
| [websocket](websocket/) | 연결을 유지하면서 클라이언트와 서버가 양방향으로 메시지를 주고받는 프로토콜입니다. |
| [webhooks](webhooks/) | 특정 이벤트가 발생하면 등록된 URL로 HTTP 요청을 보내 알리는 방식입니다. |

## 계약·설계·검증

| 폴더 | 설명 |
|---|---|
| [contracts](contracts/) | API의 요청·응답 형식과 규칙을 명세로 정의합니다. |
| [design](design/) | 오류 응답, 버전 관리, 시간 제한, 재시도, 중복 처리와 호출량 제한을 다룹니다. |
| [testing](testing/) | API 계약과 시스템 간 연계 동작을 검사합니다. |

인증·권한 위임·API 키는 공통 [Auth](../auth/README.md)에서 다룹니다.
