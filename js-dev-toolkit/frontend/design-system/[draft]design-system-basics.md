## 디자인 시스템이란

디자인 시스템은 여러 화면을 같은 기준으로 만들고 유지하기 위한 공통 약속과 재사용 요소의 모음입니다. 색과 글자 모양 같은 시각 기준부터 버튼·입력창 같은 UI 조각, 자주 반복되는 화면 흐름까지 포함할 수 있습니다. [GOV.UK Design System](https://design-system.service.gov.uk/)도 스타일, 컴포넌트, 패턴을 함께 안내합니다.

쉽게 말해, 화면을 만들 때 매번 “버튼은 무슨 색이지?”, “오류 문구는 어디에 보여주지?”를 새로 결정하지 않도록 해주는 공통 기준입니다.

## 무엇으로 이루어지는가

| 구성 | 뜻 | 예 |
|---|---|---|
| 원칙 | 화면과 상호작용을 만들 때 따를 기준 | 일관성, 명확한 피드백, 접근성 고려 |
| 스타일 | 화면 전체에 적용되는 시각 규칙 | 색상, 글꼴, 간격, 테두리 |
| 디자인 토큰 | 스타일 값을 이름 붙여 재사용하는 방식 | `color-primary`, `space-2`, `font-size-body` |
| 컴포넌트 | 여러 화면에서 다시 쓰는 UI 조각 | 버튼, 입력창, 체크박스 |
| 패턴 | 여러 컴포넌트를 엮어 반복되는 일을 돕는 화면 흐름 | 회원가입, 주소 입력, 오류 복구 |

토큰은 이름이 붙은 공통 값입니다. 예를 들어 주요 버튼 색을 각 화면에 직접 적는 대신 `color-primary`라는 이름으로 정해 두면, 버튼과 링크가 같은 색 기준을 공유하고 색을 바꿀 때도 한 곳에서 관리할 수 있습니다.

## 버튼으로 살펴보기

1. **스타일을 정합니다.** 주요 버튼은 같은 색과 글자 크기를 사용합니다.
2. **값에 이름을 붙입니다.** 색은 `color-primary`, 글자 크기는 `font-size-button`처럼 정의합니다.
3. **컴포넌트를 만듭니다.** 버튼 모양뿐 아니라 기본·비활성·로딩 상태와 키보드 사용 규칙을 함께 정합니다.
4. **패턴에서 조합합니다.** 예를 들어 가입 양식에서 입력창, 오류 안내, 제출 버튼을 일정한 순서와 규칙으로 배치합니다.

이렇게 하면 각 페이지가 버튼의 색과 상태를 제각각 구현하지 않고, 같은 기준을 공유할 수 있습니다. 컴포넌트는 화면에서 재사용하는 UI 부분이며, 패턴은 특정 사용자 작업을 완수하도록 컴포넌트를 조합한 방법입니다. [컴포넌트 설명](https://design-system.service.gov.uk/components/)과 [패턴 설명](https://design-system.service.gov.uk/patterns/)에서 이 차이를 확인할 수 있습니다.

## 왜 사용하는가

공통 기준이 있으면 화면마다 다른 표현을 줄이고, 이미 만든 UI를 다시 사용할 수 있습니다. 그 결과 새 화면을 만들 때 반복 결정을 줄이고, 변경할 때 여러 화면을 일일이 찾아 고치는 부담도 줄어듭니다.

디자인 시스템을 도입했다고 화면이 저절로 사용하기 쉬워지는 것은 아닙니다. 실제 사용 맥락과 접근성을 확인하고, 공통 컴포넌트가 필요한 작업을 제대로 지원하는지 점검해야 합니다. GOV.UK도 공통 스타일과 컴포넌트를 제공하더라도 접근성 확인과 서비스별 검토가 필요하다고 안내합니다. [접근성 전략](https://design-system.service.gov.uk/accessibility/accessibility-strategy/)

## 어디서 시작하는가

처음부터 많은 토큰이나 컴포넌트를 만들 필요는 없습니다. 먼저 반복해서 쓰는 버튼·입력창·오류 안내를 살펴보고, 공통으로 지켜야 할 색·간격·상태 규칙부터 정리하면 됩니다.

이 자료에서는 다음 순서로 이어가면 이해하기 쉽습니다.

1. 스타일과 디자인 토큰이 화면에 어떻게 적용되는지 살펴봅니다.
2. 버튼·입력창 같은 컴포넌트의 역할과 상태를 정리합니다.
3. 여러 컴포넌트를 묶는 패턴과 접근성 기준을 확인합니다.
4. 디자인 기준을 코드와 문서에서 함께 유지하는 방법을 다룹니다.
